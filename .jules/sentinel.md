## 2026-03-07 - SSRF and Path Traversal via Unvalidated API Proxy Parameters
**Vulnerability:** Upstream proxy routes `/episodes` and `/anime/:id` concatenated user-provided parameters directly into outbound Axios requests to the external Jikan API (`https://api.jikan.moe/v4/anime/${id}/episodes` and `${JIKAN_BASE}/anime/${id}`) without input validation or type checking. Attackers could supply path traversal sequences (e.g. `../../`) or domain-targeting payloads to traverse upstream endpoints or trigger unintended HTTP requests.
**Learning:** API proxy layers often assume numeric IDs from frontend consumers, but when querying parameters directly from express `req.query` or `req.params`, input must be treated as untrusted and validated against strict types (e.g. `/^\d+$/`) before being interpolated into outbound request URLs.
**Prevention:** Strictly enforce format validation on route parameters (e.g., regex checks for positive integers `/^\d+$/`) and URL-encode dynamic values prior to constructing upstream requests. Return an explicit HTTP 400 Bad Request if parameters do not match expected schema.
